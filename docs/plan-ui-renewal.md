# UI 리뉴얼 (feat/ui-renewal)

디자인 원본은 Figma 파일 **Pablo UI**에 있습니다.
- 페이지 `최종 · Wireframe v4`: 구조
- 페이지 `디자인 · A 정밀 계측`: 시각

이 문서는 그 디자인을 앱(`src/pablo_v2/skill/viewer.py`, `desktop/`)에 옮기는 계획과 진행 상황입니다.

## 바뀌는 것

**화면 틀**

| 영역 | 내용 |
|---|---|
| 왼쪽 | 작업 목록 |
| 가운데 | 머리줄(이름 + 상태 칩) → 단계 막대 → 태그가 달린 대화 → 입력창 |
| 오른쪽 | 기준 · 계획 · 왜? · 근거 탭(각각 요약 한 줄). 접으면 레일 |

**단계** (작업 종류마다 다름)
- 논문 재현: 준비 → 조건 확정 → 구현·실행 → 재현 점검 → 보고서
- 논문 읽기: 준비 → 질문 → 비교표 → 정리
- 일반: 준비 → 작업 → 검토

상태는 완료 · 진행 중 · 할 수 있음 · 막힘 · 오래됨 다섯 가지입니다. 기록에서 계산하며, 순서를 강제하지 않습니다.

**팀 리뷰 반영 (10/26)**
- 자료: 줄글 대신, 머리줄 칩을 누르면 PDF / WEB 표시가 붙은 목록 카드로 봅니다.
- 모델 선택: 네이티브 드롭다운 대신 글자 버튼과 메뉴로 바꿨습니다.

**시각 (A 정밀 계측)**
- 바탕: 차가운 회색
- 선: 검은 구획선
- 모서리: 2px
- 글꼴: Pretendard(한글), Geist(라틴), Geist Mono(숫자 · 메타)
- 강조색: 주황 하나. 사람의 판단이 필요한 곳(확인 필요, 막음, 다름, 근거 강조)에만 씁니다.
- 다크 모드는 나중에 별도 팔레트로 만듭니다.

## 지킨 계약

`desktop/check.js`와 측정 세션이 기대는 것입니다. 이름은 바꾸지 않았고, 필요한 것만 추가했습니다.

- 단계 막대 안에 그대로 둔 것: `#specs .link`, `#audits .link`, `#compares .link`, `#reports .link`. id, 문구, 표시 조건이 모두 같습니다.
- 카드 안으로 옮기고 내용은 그대로인 것: `#src`(`.paper b`, `.plist`, `#src-toggle`, `[data-open-paper]`, `[data-kind]`, `[data-code]`), `$("dir")`(첫 button이 폴더 고르기)
- 입력창
  - `#chat > .composer`의 첫 button은 지금도 송신/중지입니다. 보낼 곳(`#route`)과 모델 버튼은 DOM에서 그 뒤에 두고, CSS `order`로 화면 순서를 맞췄습니다.
  - `$("model")` `<select>`는 숨겨서 남겼고, 같은 이벤트를 받습니다.
- 머리줄의 기준 · 계획 · 왜? 알약 버튼이 없어졌습니다. 테스트는 `#ptabs [data-tab=intent|plan|trace]`를 누릅니다(check.js, rc.js 수정).
- 대화의 단계 구분선은 `.msg`가 아닌 `div.divider`입니다. 태그 줄은 메시지 내용 끝의 `div.tags`이며, `p` 요소를 쓰지 않습니다.

## 확인 방법

- `python tests/skill/test_product.py`: 페이지 스크립트를 `node --check`로도 검사합니다.
- `npm --prefix desktop run check -- --ui`: 오프라인 화면 검사입니다. `PABLO_SHOTS=<폴더>`를 주면 픽스처 화면 네 장(첫 화면, 소스 카드, 기준 패널, 단계 필터)을 저장합니다.
