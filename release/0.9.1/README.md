# Pablo 0.9.1

Pablo는 ChatGPT 계정으로 Codex 에이전트를 쓰는 Windows 데스크톱 앱입니다.
작업 기준을 지키는지 Guard가 확인합니다.
논문을 재현하는 작업이면 논문의 조건을 원문 쪽에 고정하고, 코드가 그 조건에서 벗어났는지 점검합니다.
0.9.1은 0.9.0의 화면 표시 결함 두 건을 고친 판입니다. 기능과 화면 구성은 0.9.0과 같습니다.

## 0.9.0 이후 바뀐 것

시연 리허설(2026-10-27, 0.9.0 패키지 앱, 실제 계정)에서 찾은 결함입니다.

- **실행에 실패한 명령에 "막음" 머리표가 붙던 것.** 에이전트가 돌린 명령이 실패하면 "⚠ 작업을 실행하지 못했습니다" 카드가 뜹니다. 이 카드에 Guard가 막은 카드와 같은 "막음" 머리표가 붙어 있었습니다. 이제 "막음"은 Guard가 막은 카드에만 붙습니다. 실패 카드는 같은 회색 상자로 남습니다.
- **재현 점검 카드의 변경 알림에 같은 위치가 두 번 나오던 것.** 예: "점검 때 Pablo가 확인한 13곳 중 2곳이 지금은 그대로가 아닙니다(config.yaml:5, config.yaml:5)". 논문 조건과 작업 기준이 같은 줄을 가리키면 두 곳으로 셌습니다. 이제 카드와 재현 보고서 모두 파일:줄 하나를 한 곳으로 셉니다.

## 설치

0.9.0과 같습니다(`../0.9.0/README.md`의 "설치" 절). 0.9.0에서 올리면 작업, 대화, 로그인이 그대로 이어집니다.

1. `Get-FileHash .\PabloSetup.exe -Algorithm SHA256` 값이 위 SHA-256과 같은지 봅니다.
2. `PabloSetup.exe`를 실행합니다. "Windows의 PC 보호" 창이 뜨면 "추가 정보" → "실행"을 누릅니다.

| 경로 | 내용 |
|---|---|
| `%LOCALAPPDATA%\Pablo\app-0.9.1` | 앱 (읽기 전용으로 씀) |
| `%APPDATA%\pablo-desktop` | 사용자 데이터 (로그인 정보, 작업 기록, 대화, 체크포인트) |

시연 시나리오와 깨끗한 PC 점검표는 0.8.0 문서를 0.9.0의 버튼 위치 대응표(`../0.9.0/README.md`)와 함께 씁니다.

## 검증

0.9.1 설치본의 코드는 커밋 `327ff8a`(PR #9)에 버전 번호만 바꾼 것입니다.

| 점검 | 결과 |
|---|---|
| Python 테스트 (`tests/`, 파일 12개) + `desktop/check.js --ui` (로컬 CI) | 통과 |
| 새 `--ui` 단언 두 개: 막음 카드에만 "막음", 같은 줄을 가리키는 항목이 있어도 "5곳 중 1곳(config.yaml:5)" | 통과. 고치기 전 코드에서는 각각 실패함("6곳 중 2곳(config.yaml:5, config.yaml:5)") |
| 시연 리허설 (0.9.0 패키지 앱, 실제 계정, 2026-10-27): 일반 작업의 기준·보류·확인 필요·왜?·진행·변경 보기·되돌리기, 논문 재현의 조건 뽑기(25개)·PDF 강조·재현 점검·코드 줄·고친 뒤 다시 점검, arXiv 가져오기·비교표·칸 [n], 보고서 | 모두 동작. 위의 결함 두 건을 찾음 |

실제 계정 점검(`--agent`, `--guard`, `--audit`, `rc.js`)은 0.9.1로 다시 돌리지 않았습니다. 바뀐 것은 카드의 클래스와 위치를 세는 방식뿐이고, Guard 판정과 에이전트 실행은 0.9.0과 같습니다.

## 빌드 재현

```bash
npm --prefix desktop run backend
npm --prefix desktop run make
```

결과: `desktop/out/make/squirrel.windows/x64/PabloSetup.exe`
번들한 서드파티 구성 요소와 라이선스는 `THIRD_PARTY_NOTICES.txt`에 있습니다. 0.9.0과 같습니다.
