# Pablo 0.9.1 — 알려진 제한사항

이전 버전의 제한은 그대로입니다.
- 0.6.0의 1, 3, 4, 6–10번(`../0.6.0/KNOWN_LIMITATIONS.md`): 서명 없는 설치 파일, Electron fuse 미설정, PDF 첫 열기 지연, 용량, 자동 업데이트 없음, Codex crate 라이선스 목록, Windows x64 전용, 깨끗한 PC 검증 미완료.
- 0.7.0의 2, 12–14번(`../0.7.0/KNOWN_LIMITATIONS.md`): 처음 보는 읽기 명령의 Guard 지연, 되돌리기에 git 필요, 인터넷은 작업마다 직접 켬, 긴 실험은 앱 밖에서.
- 0.8.0의 11, 15–18번(`../0.8.0/KNOWN_LIMITATIONS.md`): 재현 조건과 점검은 모델의 판단(일부를 Pablo가 확인), 부록을 읽어 느려진 조건 뽑기, 표 숫자의 열 짝, PowerShell 7이 없는 PC, 바깥 서비스를 쓰는 논문 가져오기.
- 0.9.0의 19–22번(`../0.9.0/KNOWN_LIMITATIONS.md`): 한국어·밝은 테마뿐, 기록에서 계산하는 단계, 모델이 쓰는 단계 요약, 작게 남은 화면 문제.

## 23. 최종 설치본으로 다시 돌리지 않은 점검

- 실제 계정 점검(`--agent`, `--guard`, `--audit`, `rc.js`)은 0.9.1로 다시 돌리지 않았습니다(`README.md`의 "검증" 절). `rc.js`는 로그인 정보를 임시 프로필에 복사해 쓰는데, 복사본이 토큰을 갱신하면 원래 프로필의 로그인이 풀립니다.
- 깨끗한 PC 검증은 0.6.0 이후 여전히 하지 못했습니다.

## 24. 기준을 대놓고 어기는 요청은 대개 에이전트가 먼저 거절합니다

- Pablo는 작업 기준과 논문 조건을 에이전트에게 먼저 알립니다. 그래서 "반드시" 기준을 어기는 요청을 받으면 에이전트가 대개 기준을 인용하며 거절하고, 시도하지 않습니다. 이때는 Guard가 판정할 행동이 없어 막음 카드가 뜨지 않습니다. 시연 리허설에서 대놓고, 거듭, 에둘러 요청한 세 번 모두, 그리고 결과에 맞추려는 설정 변경 요청도 이렇게 끝났습니다.
- 에이전트가 시도한 행동은 그대로 Guard를 거칩니다(허용, 확인 필요, 막음).

## 25. 애매한 말을 묻는 동안 에이전트는 이미 움직일 수 있습니다

- "~면 좋을 것 같긴 한데"처럼 애매한 말은 **기준으로 추가 / 무시**를 묻지만, 같은 메시지를 받은 에이전트는 그 답을 기다리지 않고 작업할 수 있습니다(리허설에서 다크 모드를 바로 적용함). 기준으로 정한 뒤의 요청부터 그 기준이 판정에 쓰입니다.
- 한 문장에 여러 요구가 섞이면 지속 표시("절대", "반드시", "~하지 마")가 있는 것만 기준이 됩니다. 리허설에서 "외부 라이브러리 없이 HTML, CSS, JS만 써줘"는 기준이 되지 않았습니다.

## 26. 재현 점검의 "모델이 댄 위치 N곳"은 점검 행 수입니다

- 같은 줄을 가리키는 행이 둘이면 둘로 셉니다. 0.9.1이 고친 변경 알림은 위치로 세므로, 두 숫자가 다를 수 있습니다.
