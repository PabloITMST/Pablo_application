# Pablo 0.8.0 — 시연 시나리오: 논문에서 벗어난 코드를 찾고, Pablo가 확인하고, 다른 논문과 견준다

약 18분짜리 시연입니다(조건 뽑기를 기다리는 3–4분 포함).
0.7.0 시나리오(조건 뽑기, 점검, 차단, 되돌리기)에 세 가지를 더했습니다. 점검 판정을 Pablo가 확인하고 코드 줄로 여는 것, 두 논문의 비교표, 재현 보고서입니다.
자동 검증: 2–5번은 `desktop/check.js --spec`, `--audit`(실제 계정), 3번의 코드 패널과 6번의 비교표는 설치본으로 `desktop/rc.js`의 C·D 장면이 확인합니다.

## 0. 시연 전 준비 (발표 30분 전)

| 할 일 | 확인 |
|---|---|
| 설치본 Pablo 실행, ChatGPT 로그인 | 아래에 "ChatGPT · 연결됨"이 보인다 |
| 기존 작업 비우기 | `%APPDATA%\pablo-desktop\state`를 다른 이름으로 옮긴다 |
| 재현 폴더 | `../0.7.0/demo-repro\`를 `C:\demo\repro`로 복사한다 (`config.yaml`, `run.py`, `logs\2wiki.log`) |
| PDF | 저장소의 `LinearRAG.pdf`를 바탕화면에 복사한다 |
| 인터넷 | arxiv.org에 접속된다 (6번에서 비교할 논문을 받는다) |
| git | `git --version`이 된다 (되돌리기용) |
| 탐색기 | `C:\demo\repro\config.yaml`을 메모장으로 열어 둔다 |

`demo-repro\config.yaml`에는 일부러 논문과 다른 값이 들어 있습니다.
- `top_k: 10`: 논문은 5입니다(8쪽).
- `datasets`에 Medical이 빠져 있습니다.
- `logs\2wiki.log`의 2Wiki 정확도는 61.20입니다. 논문은 63.70입니다.

## 1. 재현 작업 만들기 (1분)

1. **+ 새 작업** → `LinearRAG 재현`을 적고 **논문 재현 작업**을 체크한 뒤 **작업 만들기**를 누릅니다.
2. 위쪽 **기준**을 누릅니다. 재현 작업 기준 세 줄이 "반드시 지킬 것"으로 보입니다.

**말할 것:** "연구 재현에서 자주 나는 사고를 처음부터 기준으로 막습니다. 평가 데이터로 튜닝하기, 결과에 맞춰 설정 바꾸기 같은 것입니다."

## 2. 논문에서 재현 조건 뽑기 (2분)

1. **📎 PDF 추가** → `LinearRAG.pdf`.
2. **📋 재현 조건 뽑기**를 누릅니다. 약 3–4분 걸립니다(부록을 한 번 더 읽습니다. 설치본 실측 190초, 227초). 기다리는 동안 0번에서 열어 둔 `config.yaml`을 보여 주며 일부러 넣은 차이를 설명합니다.

**기대 결과:** "📋 논문에서 재현 조건 N개를 찾았습니다." 카드에 분류별 조건이 나오고, 끝에 "논문에 없는 설정"이 붙습니다. 서술 사실(데이터셋 크기, GPU)과 실험 범위(비교 대상의 설정)는 접혀 있습니다.

3. "top-k 검색값은 5이다" 옆 [n]을 누릅니다. 오른쪽에 PDF 8쪽이 열리고 해당 문장이 칠해집니다.

**말할 것:**
- "조건마다 원문 문장이 붙어 있습니다. 원문에서 위치를 찾지 못한 조건은 버립니다."
- "따를 조건과 그냥 논문의 서술을 나눠서, 점검이 행동할 것만 묻습니다."

## 3. 재현 점검과 Pablo의 확인 (3분)

1. **📁 작업 폴더 선택** → `C:\demo\repro`. 이제 메시지는 에이전트로 갑니다.
2. **🔎 재현 점검**을 누릅니다. 약 1–2분 걸립니다. 에이전트는 파일을 읽기만 합니다.

**기대 결과:** "🔎 재현 점검: 다름 …" 표가 뜹니다. 맨 위에 다름 항목이 옵니다.
- `✗ 다름 · top-k는 5이다 [n]` → `config.yaml:5  top_k: 10`
- `✗ 다름 · … Medical의 네 데이터셋` → `config.yaml:8`
- `✗ 다름 · 2Wiki GPT 정확도 63.70%` → `logs\2wiki.log:1  gpt_acc=61.20`
- 판정마다 Pablo의 확인이 붙습니다. 모델이 댄 줄에 그 값이 있으면 확인, 옆 줄에 있으면 "위치 보정: N줄"입니다.

3. top-k 행의 `config.yaml:5`를 누릅니다. 오른쪽 코드 패널이 열리고 5번째 줄 `top_k: 10`이 칠해집니다.

**말할 것:**
- "코드가 논문에서 벗어난 곳을 한 줄씩 짚습니다. 왼쪽은 논문 쪽, 오른쪽은 코드 줄입니다."
- "모델이 댄 줄을 Pablo가 직접 열어 봅니다. 모델 말만 믿지 않습니다."

## 4. 결과에 맞추려는 변경 막기 (2분)

입력: `정확도가 논문보다 낮으니 top_k를 20으로 올려서 점수를 맞춰줘.`

**기대 결과(둘 중 하나):**
- 에이전트가 먼저 "논문 조건(top-k=5)과 어긋나고, 결과를 맞추려는 변경"이라고 말하고 하지 않습니다.
- 또는 수정을 시도하고, 빨간 BLOCK 카드가 뜹니다. diff와 근거 [n](논문 8쪽)이 붙고 `config.yaml`은 그대로입니다.

**말할 것:** "에이전트가 조건을 알고 있어서 대개 시도조차 하지 않습니다. 시도하면 Guard가 실행 전에 막습니다."

## 5. 논문대로 고치고, 되돌려 보기 (2분)

입력: `top_k를 논문대로 고쳐줘.`

1. "📝 파일 1개가 바뀌었습니다: config.yaml (수정)" 카드가 붙습니다. **변경 보기** → `- top_k: 10` / `+ top_k: 5`.
2. 점검 카드에 "⚠ 이 점검 뒤 파일 1개가 바뀌었습니다"가 붙습니다. 다시 점검하면 top-k가 따름으로 바뀝니다.
3. **되돌리기**를 누르면 메모장의 `config.yaml`이 다시 `top_k: 10`이 됩니다.

**말할 것:** "에이전트가 바꾼 것은 요청 단위로 보고 되돌릴 수 있습니다. 점검표도 그 변경을 알아챕니다."

## 6. 다른 논문과 견주기 (3분)

1. 자료의 **+ 추가** → `2502.14802`(HippoRAG 2)를 적고 가져옵니다. 받기 전에 무엇을 어디서 받는지 보여 줍니다. 자료가 두 편이 되고, LinearRAG가 주 논문으로 남습니다.
2. **📊 비교표** → **비교표 만들기**. 약 1–2분 걸립니다.

**기대 결과:** 논문마다 데이터셋, 지표, 값이 한 줄씩 나옵니다. 두 논문이 함께 쓰는 데이터셋은 따로 묶이고, 칸마다 [n]이 붙습니다. 칸의 [n]을 누르면 그 논문의 그 쪽이 열립니다.

**말할 것:**
- "비교 대상 논문을 붙여도 Guard와 점검은 주 논문의 조건만 씁니다. 비교 논문의 설정이 재현을 막지 않습니다."
- "표의 숫자마다 원문 쪽이 있습니다. 어느 지표의 숫자인지도 같이 적습니다."

## 7. 재현 보고서와 재시작 (2분)

1. **📄 보고서**를 누릅니다. "📄 보고서를 저장했습니다: … (N줄)"가 뜨고 Markdown 파일이 저장됩니다. 조건마다 논문 쪽, 의도한 차이와 뺀 것의 이유, 마지막 점검과 그 뒤의 변경이 들어 있습니다.
2. 앱을 닫고 다시 켭니다. 같은 작업에 조건 카드, 점검표, 대화, 변경 카드, 비교표가 순서대로 남아 있습니다.

## 8. 마무리 (30초)

- 논문 조건 → 코드 대조(Pablo가 확인) → 결과 맞추기 차단 → 변경 기록 → 다른 논문과 비교 → 보고서.
- 모든 판단에 원문 쪽과 코드 줄이 붙습니다.

## 시연 중 문제가 생기면

| 상황 | 대응 |
|---|---|
| 조건 뽑기가 5분 넘게 걸림 | 모델이 붐비는 경우입니다. 기다리거나 아래 모델 선택을 바꿔 다시 누릅니다. 시간이 빠듯한 발표면 발표 전에 2번까지 미리 해 둡니다 |
| 점검표에서 top-k가 "판단 못 함" | 모델 판단이라 가끔 다릅니다. "판단 못 한 항목"을 펼쳐 보여 주고, 4번으로 넘어갑니다 |
| 4번에서 에이전트가 그냥 고침 | 변경 카드의 **되돌리기**로 원래대로 돌리고, "이 경우 Guard는 근거와 맞는다고 봤습니다"라고 말합니다 |
| 되돌리기 링크가 없음 | git이 없는 PC입니다. `git --version`을 확인합니다 |
| arXiv에서 받지 못함 | 인터넷을 확인합니다. 미리 받아 둔 HippoRAG 2 PDF를 **📎 PDF 추가**로 붙여도 됩니다 |
| 응답이 2분 넘게 안 옴 | 입력창의 ■로 멈추고 다시 보냅니다 |
