# Pablo 0.8.0 — 알려진 제한사항

0.6.0의 1, 3, 4, 6–10번은 그대로입니다(`../0.6.0/KNOWN_LIMITATIONS.md`): 서명 없는 설치 파일, Electron fuse 미설정, PDF 첫 열기 지연, 용량, 자동 업데이트 없음, Codex crate 라이선스 목록, Windows x64 전용, 깨끗한 PC 검증 미완료.
0.7.0의 2, 12–14번도 그대로입니다(`../0.7.0/KNOWN_LIMITATIONS.md`): 처음 보는 읽기 명령의 Guard 지연, 되돌리기에 git 필요, 인터넷은 작업마다 직접 켬, 긴 실험은 앱 밖에서.

## 11. 재현 조건과 점검은 모델의 판단입니다 (일부를 Pablo가 확인)

- 조건 문장은 모델이 고르고, Pablo가 원문에서 위치를 확인한 것만 남깁니다. 어떤 조건을 고를지와 문장 요약은 모델이 정합니다.
- 다른 논문 세 편에서 사람이 확인한 정답 조건의 43~73%를 뽑았습니다(`docs/eval/README.md`). 표에만 있는 설정, 실험이 여럿인 논문의 실험별 설정을 놓치기 쉽습니다. 빠진 조건은 PDF에서 문장을 골라 직접 더합니다.
- 같은 논문이라도 실행마다 뽑는 조건이 바뀝니다. 다시 뽑아도 사용자가 더하거나 뺀 조건은 남습니다.
- 점검 판정(따름, 다름, 아직 없음)은 모델이 코드를 읽고 내립니다. 0.8.0부터 Pablo가 판정의 파일:줄에 그 값이 있는지 직접 확인합니다. 판정 자체(그 값이 논문과 다른가)를 다시 확인하지는 않습니다.
- 위치 없이 온 판정("아직 없음" 등)은 Pablo가 확인할 수 없습니다. 큰 저장소에서는 이런 판정이 많아질 수 있습니다.

## 15. 조건 뽑기가 부록을 한 번 더 읽어 느려졌습니다

- 참고문헌 뒤에 쪽이 있는 논문은 모델을 한 번 더 부릅니다. 다른 논문 세 편에서 1.4~2배(80–126초), 설치본의 LinearRAG에서 190–227초가 걸렸습니다(0.7.0은 43초).
- 부록에서 정답에 없는 항목(부가 분석의 설정 등)이 섞여 조건 수가 늘 수 있습니다.

## 16. 표의 숫자는 열 짝이 틀릴 수 있습니다

- PDF 텍스트에는 표의 열 이름이 없는 경우가 많습니다. 표 한 행을 인용한 결과 조건은 "? 열 짝 확인 필요"로 보이고, 확인 전에는 판정하지 않습니다.
- 비교표의 숫자도 같습니다. 칸의 [n]을 눌러 원문 표에서 열을 확인합니다.

## 17. PowerShell 7이 없는 PC

- 에이전트가 쓰는 Windows PowerShell 5.1은 BOM 없는 UTF-8 파일을 cp949로 읽습니다. 한글 주석이 든 코드에서 인용이 깨질 수 있습니다.
- Pablo는 로그인 뒤 한 번 설치를 안내하고, 에이전트에게 UTF-8로 읽으라고 알립니다. 이 완화책을 PowerShell 7이 없는 실제 PC에서 확인하지는 못했습니다.

## 18. 논문 가져오기는 바깥 서비스를 씁니다

- arXiv 번호·검색, OpenReview, DOI(Crossref) 조회는 입력한 번호나 검색어를 그 서비스로 보냅니다. 앱이 무엇을 어디로 보냈는지 화면에 적습니다.
- DOI로 찾은 논문의 arXiv 판은 출판본과 다를 수 있습니다. 출판사 PDF는 직접 받아 **📎 PDF 추가**로 붙입니다.
