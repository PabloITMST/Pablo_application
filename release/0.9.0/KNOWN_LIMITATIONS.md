# Pablo 0.9.0 — 알려진 제한사항

이전 버전의 제한은 그대로입니다.
- 0.6.0의 1, 3, 4, 6–10번(`../0.6.0/KNOWN_LIMITATIONS.md`): 서명 없는 설치 파일, Electron fuse 미설정, PDF 첫 열기 지연, 용량, 자동 업데이트 없음, Codex crate 라이선스 목록, Windows x64 전용, 깨끗한 PC 검증 미완료.
- 0.7.0의 2, 12–14번(`../0.7.0/KNOWN_LIMITATIONS.md`): 처음 보는 읽기 명령의 Guard 지연, 되돌리기에 git 필요, 인터넷은 작업마다 직접 켬, 긴 실험은 앱 밖에서.
- 0.8.0의 11, 15–18번(`../0.8.0/KNOWN_LIMITATIONS.md`): 재현 조건과 점검은 모델의 판단(일부를 Pablo가 확인), 부록을 읽어 느려진 조건 뽑기, 표 숫자의 열 짝, PowerShell 7이 없는 PC, 바깥 서비스를 쓰는 논문 가져오기.

## 19. 화면은 한국어, 밝은 테마뿐입니다

- 화면 글은 한국어만 있습니다.
- 어두운 테마는 아직 없습니다. Windows가 어두운 모드여도 밝게 보입니다.

## 20. 단계는 기록에서 계산합니다

- 메시지의 단계 태그는 그 기록이 무엇인지(조건 뽑기, 점검, 에이전트 요청, 보고서 등)로 정합니다. 대화 내용을 읽고 정하지 않습니다. 맞지 않으면 **✎ 태그**로 바꿉니다. 사람이 바꾼 태그가 이깁니다.
- 0.8.0에서 만든 작업의 종류는 자료와 폴더로 짐작합니다(`README.md`의 "설치" 절). 작업 종류를 나중에 바꾸는 메뉴는 없습니다.

## 21. 단계 요약은 모델이 씁니다

- **✦ 요약 쓰기**는 작업 목표와 그 단계의 메시지(최근 80개, 메시지마다 앞 2,000자)만 모델에 보냅니다. 그보다 오래된 메시지는 요약에 들어가지 않습니다. QA에서 다섯 단계 모두 메시지 밖 사실을 지어내지 않았지만, 보장하지는 않습니다.
- 사람이 고친 요약에는 "그 뒤 메시지 N개" 알림이 붙지 않습니다. 사람이 쓴 요약이 낡아도 화면이 알려 주지 않습니다.

## 22. 작게 남은 화면 문제

- 에이전트 답의 Markdown(목록, `코드`)은 서식 없이 글자 그대로 보입니다. 0.8.0과 같습니다. 0.9.0은 단계 요약만 고쳤습니다.
- 소스 카드에서 arXiv로 받은 두 번째 논문의 이름이 파일 이름(`arxiv-2406.03150v1` 등)으로 보일 수 있습니다. 소스 카드의 ✎로 이름을 바꿉니다.

## 23. 최종 설치본으로 다시 돌리지 않은 점검

- 실제 계정 `rc.js`는 같은 코드(`6c608a0`)로 패키징한 앱에서 통과했고, 0.9.0 번호를 단 최종 설치본으로는 다시 돌리지 않았습니다(`README.md`의 "검증" 절).
- 깨끗한 PC 검증은 0.6.0 이후 여전히 하지 못했습니다.
