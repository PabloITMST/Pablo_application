# Pablo 0.11.0

Pablo는 ChatGPT 계정으로 Codex 에이전트를 쓰는 Windows 데스크톱 앱입니다.
작업 기준을 지키는지 Guard가 확인합니다.
논문을 재현하는 작업이면 논문의 조건을 원문 쪽에 고정하고, 코드가 그 조건에서 벗어났는지 점검합니다.
0.11.0은 화면을 영어로 바꿀 수 있는 판입니다. 캡스톤 발표 영상을 영어로 찍기 위해 만들었습니다. 기본은 한국어 그대로입니다.

## 0.10.1 이후 바뀐 것

### 영어 화면

- **설정 · 기본값 · 언어 · Language**에서 **English**를 고르면 창을 다시 그려 영어로 엽니다. 에이전트가 작업하는 중에는 바꾸지 않습니다. 고른 언어는 다음 실행에도 남습니다.
- **화면 글자.** 사이드바, 머리줄, 단계 막대, 대화 카드, 오른쪽 패널, 대화상자, 설정, 오류 문구가 영어입니다. 파일 고르기 창의 제목도 영어입니다.
- **Pablo가 새로 쓰는 문장.** 영어로 고른 뒤에는 다음도 영어로 씁니다.
  - 재현 조건과 논문에 없는 설정
  - 논문 질문의 답
  - 재현 점검의 판단 메모와 요약
  - Guard 카드의 이유
  - 목표 이탈 카드와 기준 변경 카드
  - 단계 요약
  - 비교표의 기본 열
  - 논문 재현 작업의 기본 기준 세 줄
- **에이전트에게 주는 지시문(기준·근거 목록)도 영어**로 씁니다. 그래서 에이전트도 영어로 답합니다.
- **영어 대화도 기준으로 읽습니다.** "If possible, don't …"는 가능하면 기준, "Never …"는 반드시 기준이 되고, "might be easier" 같은 말은 기준으로 둘지 묻습니다. "Create …", "Please …" 같은 요청은 기준이 되지 않습니다.
- 이미 저장된 한국어 글과 보고서 내보내기는 그대로입니다(`KNOWN_LIMITATIONS.md` 36번).

### 그 밖

- 로컬 점검 `desktop/check.js --ui`가 끝에 영어 화면을 엽니다. 픽스처의 데이터가 아닌 한국어가 화면에 남으면 실패합니다(`--ui-en`으로 그것만 돌립니다).
- `tests/skill/test_i18n.py`는 다음을 확인합니다.
  - 화면에 나올 수 있는 한국어 문자열마다 영어가 있는지
  - CSS가 직접 쓰는 글자마다 영어가 있는지
  - 프롬프트가 영어로 바뀌는지

## 설치

0.9.0과 같습니다(`../0.9.0/README.md`의 "설치" 절). 0.10.x에서 올리면 작업, 대화, 로그인이 그대로 이어집니다.

1. `Get-FileHash .\PabloSetup.exe -Algorithm SHA256` 값이 위 SHA-256과 같은지 봅니다.
2. `PabloSetup.exe`를 실행합니다. "Windows의 PC 보호" 창이 뜨면 "추가 정보" → "실행"을 누릅니다.

| 경로 | 내용 |
|---|---|
| `%LOCALAPPDATA%\Pablo\app-0.11.0` | 앱 (읽기 전용으로 씀) |
| `%APPDATA%\pablo-desktop` | 사용자 데이터 (로그인 정보, 작업 기록, 대화, 체크포인트) |

## 검증

설치본의 앱 코드는 이 릴리스의 PR과 같습니다(빌드한 커밋 `b34a094`, 그 뒤로는 버전·문서만 바뀜).

| 점검 | 결과 |
|---|---|
| Python 테스트 (`tests/`, 16개) + `desktop/check.js --ui`, `--auth` (로컬 CI `npm --prefix desktop run ci`, 321초) | 통과. `--ui`는 끝에 픽스처 화면을 영어로 열어, 데이터가 아닌 한국어가 남지 않는지 봅니다(첫 화면, 패널 탭 4개, 새 작업, 설정 다섯 쪽). 새 테스트: `test_i18n.py`(키 1,145개), 영어 대화 판별, 영어 지시문 |
| 실제 계정, 캡스톤 대본 장면 5–7을 영어로 (같은 빌드, 시연 프로필, 처음 상태에서) | 통과. "If possible, don't extract function relationships with an LLM or rules." → 가능하면 기준. relations.py를 만들라는 두 요청 모두 Guard **확인 필요** 카드(3장) → 모두 취소, relations.py는 생기지 않음. 카드의 "Related criteria" · "Review" 줄과 **왜?** 패널이 영어. 실제 화면에서 번역하지 못한 글 0개(두 작업, 패널 탭 전부) |
| 실제 계정, 장면 1–4를 영어로 (한 커밋 전 빌드 `45dc6a8`) | 통과. 재현 조건 41개가 영어, "What top-k value is used for retrieval?" → 영어 답과 [1] → 8쪽 강조, 재현 점검이 영어(다름: top-k 5 ↔ `config.yaml:5` `top_k: 10`), 관계 추출 질문 → 영어 답 [1][2]. 최종 빌드에서는 작업 A를 만든 화면만 다시 봤습니다(번역 못 한 글 0개) |

에이전트의 행동은 실행마다 다릅니다. 장면 7의 첫 요청을 앞 테이크(영어, 한국어 지시문)에서는 에이전트가 기준을 인용하며 거절했고, 최종 빌드(영어 지시문)에서는 기준과 다르다고 밝힌 뒤 진행하려다 확인 카드가 떴습니다.

`--agent`, `--guard`, `--audit`, `--pdf`, `rc.js`는 돌리지 않았습니다. 설치본을 이 PC에 설치해 보지는 않았고, 같은 빌드의 `desktop/out/Pablo-win32-x64`로 시연했습니다.
