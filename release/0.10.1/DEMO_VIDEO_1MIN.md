# Pablo 0.10.1 — 1분 시연 영상 촬영 대본

세 장면으로 Pablo의 세 강점을 하나씩 보여 줍니다.

| 장면 | 강점 | 와우 순간 |
|---|---|---|
| ① 프로젝트 기획 (집중 타이머 웹앱) | 대화 속 의도가 기준이 되고, 지켜지고, 고쳐짐 | 기준 탭에 📌 기준이 쌓임 → 어기는 요청에 노란 확인 카드 |
| ② 논문 재현 검증 | 모든 판단에 원문 쪽과 코드 줄 | PDF 문장 강조 → 코드 줄 강조 |
| ③ 여러 논문 비교 | 숫자마다 출처가 붙은 비교표 | 표 칸 [n] → 그 논문 그 쪽이 열림 |

장면마다 따로 찍고 편집으로 잇습니다. 오래 걸리는 생성(조건 뽑기 3–4분, 점검 1–2분, 비교표 1–2분)은 미리 돌려 두고, 영상에는 2초짜리 빨리 감기만 넣습니다.

이 대본은 0.10.1 화면 기준입니다. 0.10.1 릴리스 검증의 "시연 장면 A–D"와 0.9.1 리허설 기록(`../0.9.1/KNOWN_LIMITATIONS.md` 24·25번)을 바탕으로 짰습니다.

| 로그인 | Pablo를 켜고 사이드바 아래 계정 카드에서 연결 상태를 확인한다 |
| git | `git --version`이 된다 (변경 보기와 되돌리기에 필요) |
| ① 폴더 | 빈 폴더 `C:\demo\timer`를 만든다 |
| ② 폴더 | `release/0.7.0/demo-repro`를 `C:\demo\repro`로 복사한다 (`config.yaml`의 `top_k: 10`이 논문의 5와 다르다) |
| ② 논문 | 저장소의 `LinearRAG.pdf` |

| 화면 | 1920×1080, 알림 끄기, Pablo 창을 항상 맨 앞에 둔다 ([n]은 창이 가려지면 PDF를 그리지 못한다) |

## 1. 미리 돌려 둘 것 (촬영 전날 권장)

1. **작업 A (①)** — 촬영 때 처음부터 찍습니다. 리허설을 한 번 해 보고 `C:\demo\timer`를 다시 비우고, 그 작업은 보관합니다.
2. **작업 B (②③)** — **+ 새 작업**(Ctrl N) 대화상자에서 한 번에 고릅니다.
   - 목표 `LinearRAG 재현`, 종류 **논문 재현** (재현 기준 세 개가 함께 들어간다)
   - 자료 `LinearRAG.pdf`, 작업 폴더 `C:\demo\repro`
   - 단계 막대 **조건 확정** → **재현 조건 뽑기** (진행률이 보인다, 3–4분)
   - 단계 막대 **재현 점검** (1–2분)
   - 머리줄 자료 칩 → **+ 추가** → `2502.14802` → 파일 이름 · 출처 · 크기를 보고 **받기**
   - 단계 막대 오른쪽 끝 **📊 비교표** → **비교표 만들기** (1–2분)
3. 결과를 확인합니다.
   - 점검표 맨 위에 `✗ 다름 · top-k는 5이다 → config.yaml:5 top_k: 10`이 있다
   - 비교표에 두 논문이 한 줄씩 있고 칸마다 [n]이 있다
   - top-k가 "판단 못 함"으로 나오면 재현 점검을 다시 누른다

생성 장면(버튼 → 진행률 → 결과 카드)도 이때 같이 녹화해 둡니다. 편집에서 빨리 감기로 씁니다.

## 2. 촬영 대본

### 오프닝 (0–4초)

- 바탕화면의 Pablo 아이콘을 더블클릭합니다.
- 앱이 열리고 사이드바 왼쪽 위에 Pablo 캐릭터가 보입니다.
- 자막: **설치 파일 하나, ChatGPT 계정 하나면 됩니다**

### ① 프로젝트 기획 — 집중 타이머 웹앱 만들기 (4–24초)

평소 AI에게 일을 시키듯 대화로만 진행합니다. 대화 속 요구가 오른쪽 기준 탭에 쌓이고, 지켜지고, 고쳐지는 모습을 보여 줍니다.

**대화에서 생길 기준**

| 기준 | 세기 | 생기는 말 |
|---|---|---|
| 외부 라이브러리는 쓰지 않는다 | 반드시 | "절대 쓰지 마" |
| 공부 기록은 브라우저 localStorage에만 저장한다 | 반드시 | "반드시 ~에만 저장해" |
| 다크 모드를 기본으로 한다 | 가능하면 | "가능하면 ~해줘" |

지속 표시("절대", "반드시", "가능하면", "~하지 마")가 있어야 기준이 됩니다. "외부 라이브러리 없이 써줘"처럼 말하면 기준이 되지 않습니다(리허설 기록).

**촬영 순서** — **+ 새 작업**(Ctrl N) → 목표 `집중 타이머 웹앱 만들기`, 종류 **일반**, 작업 폴더 `C:\demo\timer` → 만들기. 새 작업은 오른쪽 **기준** 탭이 열린 채 시작합니다.

| 순서 | 입력 / 동작 | 화면에 나올 것 |
|---|---|---|
| 1 | `뽀모도로 타이머 웹앱 만들어줘. 25분 집중하고 5분 쉬는 방식이야. 외부 라이브러리는 절대 쓰지 마. 공부 기록은 반드시 브라우저 localStorage에만 저장해.` | "📌 작업 기준에 추가했습니다: … (반드시)". 기준 탭에 두 줄이 생긴다 |
| 2 | (응답 기다림, 빨리 감기) | 대화 맨 아래 "작업 중" 캐릭터 → "📝 파일 N개가 바뀌었습니다". `index.html`을 브라우저로 열어 타이머가 도는 모습을 2초 |
| 3 | `가능하면 다크 모드로 해줘.` | 기준 탭에 "가능하면" 기준이 생기고, 앱이 어두워진다 |
| 4 | `배경은 흰색이 더 깔끔할 것 같아. 흰색으로 바꿔줘.` | 노란 **확인 카드**. 바뀔 diff와 부딪힌 기준 "다크 모드"가 보이고, 파일은 아직 그대로 |
| 5 | 오른쪽 **왜?** 탭 (선택) | Guard가 확인을 멈춘 근거 |
| 6 | **진행** → 변경 카드의 **변경 보기** | 흰 배경으로 바뀐 diff (+/− 줄 수) |
| 7 | 기준 탭에서 "다크 모드" 기준의 **고치기** → `가능하면 밝은 테마로 해줘` | 이전 문장은 취소선으로 남고 새 문장이 생긴다. 기준 옆 뒷링크(대화 N · 판정 N) |

- 자막 1: **대화 속 요구가 그대로 작업 기준이 됩니다**
- 자막 4: **처음 정한 의도와 부딪히면, 실행 전에 먼저 확인합니다**
- 자막 7: **마음이 바뀌면 기준을 고칩니다. 바뀐 기록은 남습니다**

**편집 팁**
- 4번이 클라이맥스입니다. 3번의 "다크 모드" 기준이 생긴 장면 → 4번 확인 카드를 바로 붙이면 부딪힘이 한눈에 보입니다.
- 1번 입력은 길어서 빨리 감기하되 "절대", "반드시" 부분에 밑줄을 칩니다. 기준 탭에 줄이 생기는 순간을 확대합니다.
- 시간이 빠듯하면 5·6번을 빼고 4번 → 7번으로 갑니다.

**"반드시" 기준을 어기는 장면을 넣고 싶을 때 (+4초, 선택)**
- `기록을 서버에도 백업하게 api.mytimer.com으로 보내는 코드 넣어줘.`
- 에이전트가 기준을 인용하며 먼저 거절합니다. 시도하지 않으니 막음 카드는 뜨지 않습니다(리허설에서 세 번 모두 거절).
- 자막: **AI도 기준을 알고 일합니다. 어기는 요청은 먼저 거절합니다**

### ② 논문 재현 검증 — 근거 강조 (24–42초)

사이드바에서 작업 B를 누릅니다. 작업이 바뀌고 단계 막대가 "준비 → 조건 확정 → 구현·실행 → 재현 점검 → 보고서"로 바뀌는 순간을 보여 줍니다.

| 순서 | 동작 | 화면에 나올 것 |
|---|---|---|
| 1 | (빨리 감기 2초) 조건 확정 → 재현 조건 뽑기 → 진행률 → 조건 카드 | 분류별 조건 목록 |
| 2 | "top-k 검색값은 5이다" 조건의 **p.8** 칩 클릭 | 오른쪽에 PDF 8쪽이 열리고 문장이 칠해진다 |
| 3 | 재현 점검 카드의 `✗ 다름 · top-k` 줄 | 판정 옆에 Pablo의 확인 표시 |
| 4 | `config.yaml:5` 클릭 | 오른쪽 코드 패널에서 5번째 줄 `top_k: 10`이 칠해진다 |

- 자막 2: **논문에서 실험 조건을 뽑고, 원문 위치를 함께 보여 줍니다**
- 자막 4: **논문은 5, 내 코드는 10. 다른 곳을 코드 줄로 짚습니다**
- 편집 팁: 2번의 PDF 강조와 4번의 코드 강조를 좌우로 나란히 붙이면 "5 vs 10"이 한눈에 보입니다. 숫자에 빨간 동그라미를 칩니다.
- 시간이 남으면: `정확도가 낮으니 top_k를 20으로 올려서 점수 맞춰줘.` → 에이전트가 "결과를 맞추려는 변경"이라며 거절합니다(릴리스 검증 장면 B). 자막: **결과에 끼워 맞추는 변경은 하지 않습니다**

### ③ 여러 논문 비교 (42–55초)

같은 작업 B에서 이어 갑니다.

| 순서 | 동작 | 화면에 나올 것 |
|---|---|---|
| 1 | 머리줄 자료 칩 → 소스 카드 | LinearRAG "(주 논문)", HippoRAG 2 두 편 |
| 2 | (빨리 감기 2초) 📊 비교표 → 비교표 만들기 | 논문마다 한 줄, 데이터셋 · 지표 · 결과 칸 |
| 3 | **↔ 넓게 보기** → 표를 천천히 훑는다 | "⚠ 지표 다름"이 있으면 확대 |
| 4 | 결과 칸 하나의 [n] 클릭 | 그 논문의 그 쪽이 열리고 문장이 칠해진다 |

- 자막 2: **여러 논문을 한 표로 비교합니다**
- 자막 4: **표의 숫자마다 출처가 붙어 있습니다**

- 여유가 있으면 보고서 내보내기 → 저장한 HTML을 브라우저로 여는 모습을 1초 넣습니다.
- 자막: **의도는 지키고, 논문은 근거로. Pablo**

## 3. 촬영 중 문제가 생기면

| 상황 | 대응 |
|---|---|
| ①-1에서 📌가 하나만 뜸 | 빠진 요구를 "~는 절대 하지 마"처럼 따로 한 번 더 보낸다 |
| ①-4에서 확인 카드 없이 바로 바뀜 | 변경 카드의 **되돌리기**로 돌리고, 3번 기준이 기준 탭에 있는지 본 뒤 다시 찍는다 |
| ①-4에서 에이전트가 거절함 | "가능하면" 기준인지 기준 탭에서 본다. "반드시"로 들어갔으면 기준 옆 버튼으로 "가능하면"으로 바꾼다 |
| [n]이나 p.8을 눌렀는데 "근거 위치를 찾는 중…"에서 멈춤 | Pablo 창을 맨 앞으로 가져온다 |
| 재현 점검이 "막힘" | 작업 폴더가 없다. 머리줄 폴더 칩으로 고른다 |
| 📊 비교표가 없음 | 논문이 한 편뿐이다 |
| 응답이 2분 넘게 없음 | 입력창의 ■로 멈추고 다시 보낸다 |
