# Pablo 0.10.0 — 알려진 제한사항

이전 버전의 제한은 그대로입니다.
- 0.6.0의 1, 3, 4, 6–10번(`../0.6.0/KNOWN_LIMITATIONS.md`): 서명 없는 설치 파일, Electron fuse 미설정, PDF 첫 열기 지연, 용량, 자동 업데이트 없음, Codex crate 라이선스 목록, Windows x64 전용, 깨끗한 PC 검증 미완료.
- 0.7.0의 2, 12–14번(`../0.7.0/KNOWN_LIMITATIONS.md`): 처음 보는 읽기 명령의 Guard 지연, 되돌리기에 git 필요, 인터넷은 작업마다 직접 켬, 긴 실험은 앱 밖에서.
- 0.8.0의 11, 15–18번(`../0.8.0/KNOWN_LIMITATIONS.md`): 재현 조건과 점검은 모델의 판단(일부를 Pablo가 확인), 부록을 읽어 느려진 조건 뽑기, 표 숫자의 열 짝, PowerShell 7이 없는 PC, 바깥 서비스를 쓰는 논문 가져오기.
- 0.9.0의 19–22번(`../0.9.0/KNOWN_LIMITATIONS.md`): 한국어·밝은 테마뿐, 기록에서 계산하는 단계, 모델이 쓰는 단계 요약, 작게 남은 화면 문제.
- 0.9.1의 24–26번(`../0.9.1/KNOWN_LIMITATIONS.md`): 기준을 대놓고 어기는 요청은 에이전트가 먼저 거절함, 애매한 말을 묻는 동안 에이전트가 움직일 수 있음, 점검 행 수와 위치 수의 차이.

23번(최종 설치본으로 다시 돌리지 않은 점검)은 아래 27번으로 바뀌었습니다.

## 27. 실제 계정으로 확인하지 않은 것

- 실제 계정 점검(`--agent`, `--guard`, `--audit`, `rc.js`)은 0.10.0으로 돌리지 않았습니다(`README.md`의 "검증" 절). `rc.js`는 로그인 정보를 임시 프로필에 복사해 쓰는데, 복사본이 토큰을 갱신하면 원래 프로필의 로그인이 풀립니다.
- 0.10.0에서 새로 생긴 것 중 다음은 픽스처와 가짜 서버로만 확인했습니다: 생각 수준 전송, 조건 뽑기 진행률과 중지, 플랜 다시 확인, 새 작업 대화상자의 PDF·폴더 붙이기, arXiv 받기 확인.
- 근거가 없을 때 쪽 번호를 밝히라는 말을 brief에서 빼는 수정은 실제 모델로 확인하지 않았습니다.
- 깨끗한 PC 검증은 0.6.0 이후 여전히 하지 못했습니다.

## 28. 기기 코드로 연결할 수 없습니다

- 로그인은 시스템 브라우저에서 승인하는 방식뿐입니다. 로그인 서버(auth.openai.com)가 기기 코드 방식을 지원하지 않습니다. 브라우저를 열 수 없는 PC에서는 연결할 수 없습니다.

## 29. 진행률은 어림값입니다

- 조건 뽑기는 논문 전체를 한 번에 모델에 보냅니다. 진행률은 모델 답에 지금까지 나온 가장 큰 쪽 번호로 어림한 값이고, 실제로 읽은 쪽이 아닙니다. 처음에는 0이다가 끝나면 전체 쪽 수가 됩니다.
- 비교표는 중지만 되고 진행률은 없습니다.

## 30. 로그 파일이 없습니다

- 앱은 로그를 파일로 남기지 않습니다. **설정 · 정보**의 로그 폴더는 "없음"으로 보입니다.
- **설정 · 저장 위치**의 체크포인트는 크기만 보이고 경로는 보이지 않습니다.

## 31. 제안 태그는 규칙으로 고릅니다

- 사람이 보낸 메시지에 붙는 "✦ 제안 · <단계>"는 메시지의 낱말("보고서", "점검", "논문", "비교" 등)과 붙은 근거로 정합니다. 모델이 내용을 읽고 고르지 않습니다.
- 맞지 않으면 **아님**을 누릅니다. 그 메시지에는 다시 묻지 않습니다.
