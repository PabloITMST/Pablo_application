# Pablo 0.10.0

Pablo는 ChatGPT 계정으로 Codex 에이전트를 쓰는 Windows 데스크톱 앱입니다.
작업 기준을 지키는지 Guard가 확인합니다.
논문을 재현하는 작업이면 논문의 조건을 원문 쪽에 고정하고, 코드가 그 조건에서 벗어났는지 점검합니다.
0.10.0은 Figma 최종 디자인 A2를 빠짐없이 구현한 판입니다. 화면 구성은 0.9.x와 같고, 그 위에 추가 화면과 상태, 생각 수준 고르기가 더해졌습니다.

## 0.9.1 이후 바뀐 것

### 새로 생긴 것

- **생각 수준.** 입력창의 "모델 · 수준" 칩에서 모델과 함께 생각 수준을 고릅니다. 그 모델이 지원하는 수준만 보이고, 답을 받는 중에는 바꿀 수 없습니다.
- **새 작업 대화상자**(Ctrl N): 목표, 기준, 종류에 더해 자료(PDF, arXiv, OpenReview, DOI), 작업 폴더, 인터넷을 만들 때 함께 고릅니다. arXiv 논문은 받기 전에 파일 이름 · 출처 · 크기를 보여 주고, **받기**를 눌러야 받습니다.
- **진행률과 중지.** 조건 뽑기는 진행률을 보이고 중지할 수 있습니다. 비교표는 중지만 됩니다.
- **보고서 내보내기 대화상자.** 넣을 구획, 형식(HTML / Markdown), 저장 위치를 고릅니다. 저장한 뒤 대화에 결과 카드가 남습니다.
- **설정**이 다섯 페이지가 되었습니다: 계정, 기본값, 셸 · 인코딩, 저장 위치, 정보. 연결 해제와 플랜 다시 확인은 **설정 · 계정**에 있습니다.
- **사이드바**: 접으면 56px 레일로 남습니다. 늘 보이는 작업 검색(Ctrl K), 작업마다 단계 진행 막대, 아래쪽 계정 카드(연결 상태). F2로 작업 이름을 바꿉니다.
- **머리줄 ⋯ 메뉴**: 이름 바꾸기, 완료, 보관, 작업 폴더 열기, 보고서.
- **대화**
  - **+ 태그** 팝오버 하나에서 단계, 대상을 고르고 **결정으로 고정**, **기준으로 만들기**를 합니다. 규칙으로 고른 제안 태그가 함께 보입니다.
  - 기준·근거·파일로 대화를 거릅니다(**대화로 거르기**).
  - Guard 카드에 배지가 붙고, 일반 작업에서는 명령을 한 카드로 모읍니다. 변경 카드는 바뀐 줄 수(+/−)를 보입니다.
  - 조건 카드와 점검 카드에 필터 칩과 배지가 붙고, 조건을 다시 뽑으면 차이 카드가 뜹니다.
- **오른쪽 열**
  - 기준 탭: 기준마다 뒷링크(대화 N · 판정 N), 고치기(이전 문장을 취소선으로 남김)와 지우기.
  - 계획 탭은 단계 목록, 왜? 탭은 타임라인으로 보입니다.
  - 근거 탭: PDF에서 인용을 찾지 못하면 비슷한 문장을 보여 줍니다. 문장을 골라 조건을 더할 수 있습니다.
  - 패널 폭은 390px이고, 넓은 비교표만 835px입니다.

### 크기 체계

같은 역할의 요소 높이가 22 · 28 · 30 · 33 · 36으로 제각각이던 것을 셋으로 정했습니다.
- 32: 한 줄에 놓이는 조작 요소(버튼, 검색, 상태 칩, 보내기)
- 24: 묶음 안의 선택지(segmented 안의 탭)
- 20: 글 안에 끼는 표시(태그, [n] 인용)

### 고친 것

10/27 효용 실험에서 드러난 결함 네 건입니다.

- **재현 작업을 둘 만들면 두 번째 작업이 기본 기준을 2개만 받던 것.** 앞 작업의 같은 문장을 "반복"으로 처리했습니다. 이제 한 작업에서 한 말은 다른 작업에만 걸린 기준을 반복·구체화·변경하지 않습니다.
- **바꿀 대상이 없는 변경 요청이 "가능하면" 기준이 되던 것.** 예: "기본값을 45분 집중, 10분 휴식으로 바꿔." 이제 대상을 찾지 못한 변경은 에이전트에게 하는 요청으로 봅니다.
- **논문이 없는 재현 작업에서 에이전트가 쪽 번호를 지어내던 것.** 확인된 근거가 없으면 brief에서 "출처와 쪽을 함께 밝히세요"를 뺍니다.
- **Guard가 허용한 명령이 실행 뒤 실패할 때마다 "작업을 실행하지 못했습니다" 카드가 뜨던 것**(실행마다 6개까지). 이제 실행 기록에만 남깁니다. 실제로 실행되지 않았을 때와, 사용자가 **진행**을 누른 작업이 실패했을 때는 카드가 남습니다.

## 0.9.x 문서를 0.10.0에서 따라 할 때

기능과 순서는 같습니다. 바뀐 자리는 다음과 같습니다.

| 0.9.x | 0.10.0 |
|---|---|
| 메시지의 **📌 기준으로** | 메시지의 **+ 태그** → **기준으로 만들기** |
| 메시지의 **✎ 태그** → 결정으로 고정 | 메시지의 **+ 태그** → **결정으로 고정** |
| 계정 카드의 연결 해제 | 계정 카드의 **설정** → **설정 · 계정** → 연결 해제 → 확인 |
| 단계 막대의 보고서 저장 | 단계 막대나 머리줄 **⋯**의 **보고서 내보내기** → 대화상자 |
| 작업을 만든 뒤 머리줄에서 자료·폴더 고르기 | 새 작업 대화상자에서 함께 고르기(머리줄 칩도 그대로 씀) |

0.8.0 시연 시나리오(`../0.8.0/DEMO_SCENARIO.md`)를 따라 할 때는 0.9.0의 대응표(`../0.9.0/README.md`)를 먼저 보고, 위 표로 한 번 더 바꿉니다.

## 설치

0.9.0과 같습니다(`../0.9.0/README.md`의 "설치" 절). 0.9.x에서 올리면 작업, 대화, 로그인이 그대로 이어집니다.

1. `Get-FileHash .\PabloSetup.exe -Algorithm SHA256` 값이 위 SHA-256과 같은지 봅니다.
2. `PabloSetup.exe`를 실행합니다. "Windows의 PC 보호" 창이 뜨면 "추가 정보" → "실행"을 누릅니다.

| 경로 | 내용 |
|---|---|
| `%LOCALAPPDATA%\Pablo\app-0.10.0` | 앱 (읽기 전용으로 씀) |
| `%APPDATA%\pablo-desktop` | 사용자 데이터 (로그인 정보, 작업 기록, 대화, 체크포인트) |

## 검증

0.10.0 설치본의 코드는 main `72cf3cf`(PR #12 병합)에 버전 번호만 바꾼 것입니다.

| 점검 | 결과 |
|---|---|
| Python 테스트 (`tests/`, 파일 13개) + `desktop/check.js --ui`, `--auth` (로컬 CI `npm --prefix desktop run ci`, 154초) | 통과 |
| `desktop/check.js --pdf` (offline) | 통과 (근거 19/19) |
| 설치본 내용 | `app.asar`의 버전 0.10.0, `resources/THIRD_PARTY_NOTICES.txt`에 제어 문자 없음 |
| PR #10 · #11 · #12 각각의 로컬 CI | 통과 (각 PR의 "검증" 절) |

실제 계정 점검(`--agent`, `--guard`, `--audit`, `rc.js`)은 0.10.0으로 돌리지 않았습니다. 생각 수준 전송, 진행률·중지, 플랜 다시 확인, 새 작업 대화상자의 PDF·폴더 붙이기, arXiv 받기 확인은 픽스처와 가짜 서버로만 확인했습니다(`KNOWN_LIMITATIONS.md` 27번).

## 빌드 재현

저장소 `README.md`의 "패키징" 절을 따릅니다.

```bash
npm --prefix desktop run backend
npm --prefix desktop run make
```

결과: `desktop/out/make/squirrel.windows/x64/PabloSetup.exe`
번들한 서드파티 구성 요소와 라이선스는 `THIRD_PARTY_NOTICES.txt`에 있습니다. 0.9.0과 같습니다.
