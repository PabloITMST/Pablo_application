# Pablo 0.7.0 — 시연 시나리오: 논문 재현이 논문에서 벗어나는 순간

약 12분짜리 시연입니다.
한 작업 안에서 논문 조건 추출, 점검, 차단, 되돌리기, 재시작을 차례로 보여 줍니다.
2–5번 흐름은 `desktop/check.js --spec`, `--audit`로 자동 검증했습니다(실제 계정).
0.6.0의 인사말 시나리오(WARN, BLOCK, PDF 인용)도 그대로 동작합니다(`../0.6.0/DEMO_SCENARIO.md`).

## 0. 시연 전 준비 (발표 30분 전)

| 할 일 | 확인 |
|---|---|
| 설치본 Pablo 실행, ChatGPT 로그인 | 아래에 "ChatGPT · 연결됨"이 보인다 |
| 기존 작업 비우기 | `%APPDATA%\pablo-desktop\state`를 다른 이름으로 옮긴다 |
| 재현 폴더 | 이 폴더의 `demo-repro\`를 `C:\demo\repro`로 복사한다 (`config.yaml`, `run.py`, `logs\2wiki.log`) |
| PDF | 저장소의 `LinearRAG.pdf`를 바탕화면에 복사한다 |
| git | `git --version`이 된다 (되돌리기용) |
| 탐색기 | `C:\demo\repro\config.yaml`을 메모장으로 열어 둔다 |

`demo-repro\config.yaml`에는 일부러 논문과 다른 값이 들어 있습니다.
- `top_k: 10`: 논문은 5입니다(8쪽).
- `datasets`에 Medical이 빠져 있습니다.
- `logs\2wiki.log`의 2Wiki 정확도는 61.20입니다. 논문은 63.70입니다.

## 1. 재현 작업 만들기 (1분)

1. **+ 새 작업** → 아래를 붙여 넣고 **논문 재현 작업**을 체크한 뒤 **작업 만들기**를 누릅니다.

```
LinearRAG 재현
```

2. 위쪽 **기준**을 누릅니다. 재현 작업 기준 세 줄이 "반드시 지킬 것"으로 보입니다.

**말할 것:** "연구 재현에서 자주 나는 사고를 처음부터 기준으로 막습니다. 평가 데이터로 튜닝하기, 결과에 맞춰 설정 바꾸기 같은 것입니다."

## 2. 논문에서 재현 조건 뽑기 (2분)

1. **📎 자료: PDF 추가** → `LinearRAG.pdf`.
2. **📋 재현 조건 뽑기**를 누릅니다. 약 40–60초 걸립니다.

**기대 결과:** "📋 논문에서 재현 조건 N개를 찾았습니다." 카드에 데이터셋, 모델, 하이퍼파라미터, 평가 지표, 비교 대상, 보고된 결과가 분류별로 나오고, 끝에 "논문에 없는 설정"(시드, 반복 횟수 등)이 붙습니다.

3. 하이퍼파라미터의 "top-k 검색값은 5이다" 옆 [n]을 누릅니다. 오른쪽에 PDF 8쪽이 열리고 해당 문장이 칠해집니다.

**말할 것:**
- "조건마다 원문 문장이 붙어 있습니다. 원문에서 위치를 찾지 못한 조건은 버립니다."
- "논문에 없는 설정은 따로 보여 줍니다. 정할 때 무엇을 근거로 정했는지 남기라는 뜻입니다."

## 3. 재현 점검 (2분)

1. **📁 작업 폴더: 선택** → `C:\demo\repro`. 도구 막대에 "💬 보낼 곳: **에이전트** · 논문 질문"이 생깁니다. 이제 메시지는 에이전트로 갑니다(논문 조건은 에이전트가 이미 압니다).
2. **🔎 재현 점검**을 누릅니다. 약 1분 걸립니다. 에이전트는 파일을 읽기만 합니다.

**기대 결과:** "🔎 재현 점검: 다름 …" 표가 뜹니다. 맨 위에 다름 항목이 옵니다.
- `✗ 다름 · 하이퍼파라미터 · top-k는 5이다 [n]` → `config.yaml:5  top_k: 10`
- `✗ 다름 · 데이터셋 · … Medical의 네 데이터셋` → `config.yaml:8`
- `✗ 다름 · 보고된 결과 · 2Wiki GPT 정확도 63.70%` → `logs\2wiki.log:1  gpt_acc=61.20`
- `• 코드가 정함 · 랜덤 시드` → `config.yaml:12  seed: 42`
- "따르는 항목"과 "판단 못 한 항목"은 접혀 있습니다.

**말할 것:** "코드가 논문에서 벗어난 곳을 한 줄씩 짚습니다. 왼쪽은 논문 쪽, 오른쪽은 코드 줄입니다."

## 4. 결과에 맞추려는 변경 막기 (2분)

입력:

```
정확도가 논문보다 낮으니 top_k를 20으로 올려서 점수를 맞춰줘.
```

**기대 결과(둘 중 하나):**
- 에이전트가 먼저 말합니다. "논문 조건(top-k=5)과 어긋나고, 결과를 맞추려는 변경입니다." 그리고 하지 않습니다.
- 또는 수정을 시도하고, 빨간 BLOCK 카드가 뜹니다. 카드에는 diff(`- top_k: 10` / `+ top_k: 20`)와 근거 [n](논문 8쪽)이 붙습니다. `config.yaml`은 그대로입니다.

**말할 것:** "에이전트가 조건을 알고 있어서 대개 시도조차 하지 않습니다. 시도하면 Guard가 실행 전에 막습니다."

## 5. 논문대로 고치고, 되돌려 보기 (2분)

입력:

```
top_k를 논문대로 고쳐줘.
```

1. 수정 뒤 "📝 파일 1개가 바뀌었습니다: config.yaml (수정)" 카드가 붙습니다.
2. **변경 보기**를 누르면 `- top_k: 10` / `+ top_k: 5`가 보입니다.
3. **되돌리기**를 누르면 메모장의 `config.yaml`이 다시 `top_k: 10`이 됩니다. "되돌렸습니다. 다음 요청 때 에이전트에게도 알립니다."가 보입니다.
4. (선택) 다시 "top_k를 논문대로 고쳐줘."를 보냅니다.

**말할 것:** "에이전트가 바꾼 것은 요청 단위로 보고 되돌릴 수 있습니다. 사용자 저장소의 git 기록은 건드리지 않습니다."

## 6. 재시작 (1분)

1. 앱을 닫고 다시 켭니다.
2. 같은 작업에 조건 카드, 점검표, 대화, 변경 카드가 순서대로 남아 있습니다.

## 7. 마무리 (30초)

- 논문 조건 → 코드 대조 → 결과 맞추기 차단 → 변경 기록.
- 모든 판단에 원문 쪽과 코드 줄이 붙습니다.

## 시연 중 문제가 생기면

| 상황 | 대응 |
|---|---|
| 조건 뽑기가 1분 넘게 걸림 | 모델이 붐비는 경우입니다. 기다리거나 아래 모델 선택을 바꿔 다시 누릅니다 |
| 점검표에서 top-k가 "판단 못 함" | 모델 판단이라 가끔 다릅니다. "판단 못 한 항목"을 펼쳐 보여 주고, 4번으로 넘어갑니다 |
| 4번에서 에이전트가 그냥 고침 | 변경 카드의 **되돌리기**로 원래대로 돌리고, "이 경우 Guard는 근거와 맞는다고 봤습니다"라고 말합니다 |
| 되돌리기 링크가 없음 | git이 없는 PC입니다. `git --version`을 확인합니다 |
| 응답이 2분 넘게 안 옴 | 입력창의 ■로 멈추고 다시 보냅니다 |
