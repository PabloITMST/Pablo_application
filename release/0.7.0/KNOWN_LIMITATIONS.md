# Pablo 0.7.0 — 알려진 제한사항

0.6.0의 1, 3, 4, 6–10번은 그대로입니다(`../0.6.0/KNOWN_LIMITATIONS.md`): 서명 없는 설치 파일, Electron fuse 미설정, PDF 첫 열기 지연, 용량, 자동 업데이트 없음, Codex crate 라이선스 목록, Windows x64 전용, 깨끗한 PC 검증 미완료.
0.6.0의 5번(PDF 질문 문장을 저장하지 않음)은 고쳤습니다.

## 2. 읽기 요청의 Guard 지연 (줄었지만 남음)

- 작업 폴더에서 파일을 읽는 명령도 하나하나 Guard 판정을 거칩니다(1회 수 초).
- 같은 행동·기준·근거라면 이전 판정을 다시 써서 두 번째부터는 모델을 부르지 않습니다.
- 재현 점검은 읽기 전용 샌드박스에서 돌아 Guard를 거치지 않습니다.
- 처음 보는 읽기 명령의 지연은 그대로입니다.

## 11. 재현 조건과 점검은 모델의 판단입니다

- 조건 문장은 모델이 고르고, Pablo가 원문에서 위치를 확인한 것만 남깁니다. 위치는 정확하지만, 어떤 조건을 고를지와 문장 요약은 모델이 정합니다.
- 점검 판정(따름, 다름, 아직 없음)도 모델이 코드를 읽고 내립니다. 파일과 줄은 근거로 붙지만 Pablo가 다시 확인하지는 않습니다.
- "판단 못 함"이 많이 나올 수 있습니다. 데이터셋 크기처럼 코드만 봐서는 확인할 수 없는 조건이 그렇습니다.
- 다시 뽑으면 이전 조건 목록을 대체합니다. 조건 수와 문장은 실행마다 조금씩 다를 수 있습니다.

## 12. 되돌리기에는 git이 필요합니다

- 변경 카드와 되돌리기는 git으로 작업 폴더 상태를 기록합니다. 기록은 Pablo 데이터 폴더 안의 별도 저장소에 남고, 사용자 `.git`에는 남기지 않습니다.
- PATH에 git이 없으면 변경 카드가 뜨지 않습니다. 앱의 다른 기능은 그대로 동작합니다.
- 다음 파일은 기록하지 않습니다. 이 파일들은 되돌릴 수 없습니다.
  - 의존성·캐시 폴더: `node_modules/`, `.venv/`, `venv/`, `__pycache__/`
  - 모델 가중치와 배열 데이터: `*.pt`, `*.ckpt`, `*.safetensors`, `*.npy`, `*.parquet` 등
  - `.gitignore`에 있는 파일
- 변경 뒤에 같은 파일이 다시 바뀌었으면 되돌리지 않습니다. 덮어쓰지 않으려는 것입니다.
- 매우 큰 작업 폴더는 첫 기록에 시간이 걸릴 수 있습니다.

## 13. 인터넷은 작업마다 직접 켭니다

- 작업 폴더 모드의 기본은 인터넷 차단입니다(Codex 샌드박스 기본값).
- `pip install`, 데이터 내려받기, `git clone`이 필요하면 도구 막대의 🌐 인터넷을 허용합니다.
- 허용해도 승인된 명령은 작업 폴더와 TEMP 밖에 쓰지 못합니다.

## 14. 긴 실험은 앱 밖에서 돌립니다

- 명령은 에이전트의 한 턴 안에서 돕니다. 몇 시간짜리 학습에는 맞지 않습니다.
- 에이전트에게는 코드 작성과 짧은 확인 실행까지 맡기고, 본 실험은 직접 돌립니다.
- 그 로그를 작업 폴더에 두면 재현 점검이 보고된 결과와 대조합니다.
