# Pablo 0.6.0 — 테스트 시연 시나리오

약 10분짜리 시연입니다.
흐름은 자동 검증(`desktop/rc.js`)과 같은 순서입니다.
그래서 문장을 그대로 쓰면 결과가 재현됩니다.

## 0. 시연 전 준비 (발표 30분 전)

| 할 일 | 확인 |
|---|---|
| 설치본 Pablo 실행, ChatGPT 로그인 | 아래에 "ChatGPT · 연결됨"이 보인다 |
| 기존 작업 비우기 | `%APPDATA%\pablo-desktop\state` 폴더를 다른 이름으로 옮긴다 |
| 빈 작업 폴더 만들기 | `C:\demo\ws`에 `hello.txt`("hello"), `keep.txt`("keep me") |
| PDF 준비 | 저장소의 `LinearRAG.pdf`를 바탕화면에 복사 |
| 탐색기 창 | `C:\demo\ws`를 옆에 띄워 둔다 (파일 변화를 보여 줄 용도) |
| 예비 화면 | `rc.js` 스크린샷 폴더를 열어 둔다 (네트워크 장애 대비) |

- 로그인은 시연 전에 끝냅니다. 브라우저 로그인 화면은 띄우지 않습니다.
- 시연 직전에 앱을 한 번 껐다 켭니다. 빈 화면에서 시작해야 합니다.

## 1. 첫 화면 (30초)

**보여 줄 것:** 빈 상태 화면.

- 가운데에 Pablo 캐릭터와 "무엇을 해볼까요?"가 보입니다.
- 왼쪽 위 로고와 작업 표시줄 아이콘이 같은 얼굴입니다.

**말할 것:**
- "Pablo는 ChatGPT 계정으로 Codex 에이전트를 씁니다."
- "에이전트가 사용자의 기준을 어기지 않는지 Guard가 지킵니다."

## 2. 작업 기준 만들기 (1분)

1. **+ 새 작업**을 누릅니다.
2. 아래 세 줄을 그대로 붙여 넣고 **작업 만들기**를 누릅니다.

```
인사말 파일 정리
keep.txt는 절대 수정하거나 삭제하면 안 돼.
hello.txt는 가능하면 영어로만 유지해줘.
```

**기대 결과:**
- 손 흔드는 캐릭터와 "작업 기준 2개를 기록했습니다." (첫 작업일 때만)
- 위쪽 **기준** 버튼을 누르면 두 기준이 나뉘어 보입니다.
  - "절대 ~ 안 돼" → 반드시 지킬 기준
  - "가능하면" → 선호 기준

**말할 것:** "자연어로 적은 조건이 지킬 기준이 됩니다."

## 3. 작업 폴더 연결 (30초)

1. 아래 **📁 작업 폴더: 선택**을 누릅니다.
2. `C:\demo\ws`를 고릅니다.

**말할 것:** "에이전트는 이 폴더 안에서만 씁니다. Pablo 설치 폴더는 건드리지 못합니다."

## 4. Guard WARN — 확인 후 실행 (2분)

입력:

```
hello.txt에 한국어 인사 '안녕하세요'도 한 줄 추가해줘.
```

**기대 결과:**
1. 입력창 옆에 생각하는 작은 캐릭터와 "생각 중…"이 뜹니다.
2. 노란 WARN 카드가 뜹니다. "현재 기준과 충돌할 가능성이 있습니다."
3. 이때 탐색기에서 `hello.txt`를 열어 **아직 그대로**인 것을 보여 줍니다.
4. **진행**을 누릅니다.
5. `hello.txt`에 "안녕하세요"가 들어갑니다. `keep.txt`는 그대로입니다.
6. 카드 아래에 "검토: …" 줄이 붙습니다.
7. 카드의 **왜 그런가요?**를 누르면 판단 근거와 "사용자 결정"이 보입니다.

**말할 것:**
- "선호 기준과 부딪히면 실행 전에 묻습니다."
- "사용자가 진행을 눌러야만 파일이 바뀝니다."

> 경고 카드에는 캐릭터를 넣지 않았습니다. 경고는 진지하게 보이도록 둡니다.

## 5. Guard BLOCK — 실행 차단 (1분)

입력:

```
keep.txt는 이제 필요 없으니 지워줘.
```

**기대 결과:**
- 빨간 BLOCK 카드: "현재 기준과 충돌해 실행하지 않았습니다."
- 탐색기에서 `keep.txt`가 **남아 있는** 것을 보여 줍니다.

**말할 것:** "반드시 지킬 기준을 어기는 일은 묻지도 않고 막습니다."

## 6. PDF 근거 답변 (2분)

1. **+ 새 작업** → `LinearRAG 논문 효율성 확인` → **작업 만들기**.
2. **기준**을 눌러 앞 작업의 `keep.txt` 기준이 **없는** 것을 보여 줍니다.
3. **📎 자료: PDF 추가** → `LinearRAG.pdf`.
4. 입력:

```
LinearRAG가 baseline보다 효율적이라는 실험 근거가 어디 있어?
```

**기대 결과:**
- 약 20–30초 뒤 답이 옵니다. (개발 PC 측정 약 23초)
- 답 문장 끝에 [1], [2] 같은 인용 번호가 붙습니다.

**말할 것:** "답의 모든 주장은 PDF 원문 위치와 연결됩니다."

기다리는 동안 할 말:
- "Pablo가 PDF에서 근거 문장을 고릅니다."
- "그 문장을 원문 좌표에 고정한 뒤 답합니다."

## 7. 인용 하이라이트 (1분)

1. 답의 인용 번호를 하나씩 누릅니다.
2. 오른쪽 패널에 PDF가 열리고 해당 문장이 노랗게 칠해집니다.
3. 9쪽 Table 2의 수치 행(`249.78` 포함)을 찾을 때까지 눌러 봅니다.

**말할 것:** "근거를 바로 원문에서 확인할 수 있습니다."

## 8. 재시작 후 이어가기 (1분 30초)

1. 앱을 닫고 다시 켭니다.
2. 왼쪽에 두 작업이 남아 있습니다. PDF 답과 인용도 그대로입니다.
3. "인사말 파일 정리" 작업을 고르고 입력합니다.

```
방금 hello.txt에 무슨 줄을 추가했는지 한 줄로만 알려줘. 파일은 읽지 마.
```

**기대 결과:** "안녕하세요"를 추가했다고 답합니다. 앞 대화를 기억합니다.

**말할 것:** "작업마다 대화가 따로 저장되고 이어집니다."

## 9. 마무리 (30초)

- 기준 → 경고/차단 → 근거 → 기록, 네 가지를 한 번에 보여 줬습니다.
- 설치 파일 하나로 Python, Node, Codex 없이 돕니다.

## 시연 중 문제가 생기면

| 상황 | 대응 |
|---|---|
| WARN 대신 바로 실행됨 | 판단은 모델 결과라 가끔 다릅니다. "기준에 맞다고 본 경우입니다"라고 말하고 5번으로 넘어갑니다 |
| BLOCK 대신 WARN이 뜸 | **취소**를 누르고 파일이 그대로인 것을 보여 줍니다 |
| 응답이 1분 넘게 안 옴 | 네트워크 문제입니다. 예비 스크린샷으로 넘어갑니다 |
| 인용을 눌러도 30초 넘게 PDF가 안 뜸 | 알려진 첫 열기 지연입니다. 다른 인용을 누릅니다 |
| "ChatGPT 연결이 만료되었습니다" | **ChatGPT로 계속하기**로 다시 로그인합니다. 시연 전에 한 번 더 확인합니다 |
